# C0 Implementation Design

**Date**: 2026-02-02
**Status**: Approved

## Overview

C0 is a hierarchical binary data stream format designed for human-readable UTF-8 environments. It uses ASCII C0 control characters (FS, GS, RS, US) as structural delimiters and printable_binary encoding for all payload data.

## Data Model

### Value Type (Tagged Union with Slices)

```zig
pub const Value = union(enum) {
    string: []const u8,
    array: []const Value,
    object: []const Entry,
};

pub const Entry = struct {
    key: []const u8,
    value: Value,
};
```

Slices enable hierarchical/recursive structure while keeping the union fixed-size.

## Structural Bytes

| Byte | Name | Hex | Purpose |
|------|------|-----|---------|
| FS | File Separator | 0x1C | Begin object |
| GS | Group Separator | 0x1D | Begin array |
| RS | Record Separator | 0x1E | Terminate object entry |
| US | Unit Separator | 0x1F | Terminate array element / separate key from value |

**Critical Invariant**: printable_binary encodes bytes 0x1C-0x1F to multi-byte UTF-8 sequences (Ξ, ǁ, ǀ, ¬), so raw structural bytes in a C0 stream are always unambiguously structural.

## Architecture (Hexagonal)

```
┌─────────────────────────────────────────────┐
│  CLI (C)            │  FFI (C ABI)          │
│  cli/main.c         │  ffi/c_api.zig        │
│  - stdin/stdout     │  - c0.h               │
│  - arg parsing      │  - arena-based memory │
└──────────┬──────────┴──────────┬────────────┘
           │                     │
           ▼                     ▼
┌─────────────────────────────────────────────┐
│              Core (Pure Zig)                │
│  src/core/                                  │
│  - Value type (string/array/object)         │
│  - encode(allocator, Value) → []u8          │
│  - decode(allocator, []u8) → Value          │
│  - printable_binary dependency              │
│  - NO I/O, NO global state                  │
└─────────────────────────────────────────────┘
```

**Why C CLI?** The CLI must only communicate with core through the FFI layer. A C CLI is self-enforcing - it physically cannot call Zig functions unless they're exported via C ABI. This prevents accidental contract violations.

## FFI Design (Arena-Based)

All allocations for a document go into a single arena, freed in one call:

```c
// c0.h
typedef struct C0Arena C0Arena;
typedef struct C0Value C0Value;

// Arena lifecycle
C0Arena* c0_arena_new(void);
void     c0_arena_free(C0Arena* arena);  // Frees everything

// Build values (allocated from arena)
C0Value* c0_string(C0Arena* arena, const char* data, size_t len);
C0Value* c0_array(C0Arena* arena);
void     c0_array_push(C0Value* arr, C0Value* item);
C0Value* c0_object(C0Arena* arena);
void     c0_object_set(C0Value* obj, const char* key, size_t key_len, C0Value* val);

// Encode/Decode
int      c0_encode(C0Arena* arena, const C0Value* val, const char** out, size_t* out_len);
C0Value* c0_decode(C0Arena* arena, const char* data, size_t len);
```

Client usage:
```c
C0Arena* arena = c0_arena_new();
C0Value* doc = c0_decode(arena, bytes, len);
// ... use doc arbitrarily deep ...
c0_arena_free(arena);  // Done
```

## Core API

```zig
// src/core/mod.zig
const std = @import("std");
const pb = @import("printable_binary");

pub const Value = @import("value.zig").Value;
pub const Entry = @import("value.zig").Entry;

/// Encode a Value to C0 binary format
pub fn encode(allocator: std.mem.Allocator, value: Value) ![]u8

/// Decode C0 binary to a Value
pub fn decode(allocator: std.mem.Allocator, bytes: []const u8) !Value

/// Free a Value and all nested allocations
pub fn deinit(allocator: std.mem.Allocator, value: *Value) void
```

## Encoding Rules (from spec)

- **String**: printable_binary encoded bytes (boundaries from context)
- **Array**: `GS` + (value `US`)* — empty array is `GS US`
- **Object**: `FS` + (key `US` value `RS`)* — empty object is `FS RS`

## Testing Strategy

### 1. Zig Unit Tests (`zig build test`)

- Round-trip: decode(encode(x)) == x
- Empty containers: `""`, `[]`, `{}`
- Nested structures
- Structural byte invariant (0x1C-0x1F never in payloads)
- Error cases: malformed input, unterminated containers

### 2. Bash CLI Tests (`tests/cli/`)

- stdin/stdout encode/decode
- File I/O
- Error exit codes
- Round-trip: `echo data | c0 encode | c0 decode`

### Master Runner (`./test`)

Accumulates failures from both suites, exits with total failure count.
